## Publication procedure

1. Compare accepted development source with the latest `main`; preserve all published history.
2. Update the version, README, changelog and release notes. Validate the staged candidate.
3. Build production assets. Use the tested installed stylesheet's exact bytes when staging the assets; validate that its normalized content matches the repository stylesheet.
4. Review the complete staged diff, check whitespace and asset/source consistency, then commit on `main` with the maintainer's existing repository identity.
5. Recheck remote `main`, push without force, create and push annotated tag `0.3.0` at that commit. Never move an existing published tag.
6. Create a draft release titled **NosyGraph 0.3.0 — Graph Tab editing, linked tabs and Lens Cut**, using `0.3.0.md` verbatim as the description. Upload the three assets and verify their sizes and SHA-256 digests before publication.
7. Publish as the latest normal release. Verify the remote main/tag commit, published description and asset names. Download each public asset and compare hashes with the staged files. Store the release receipt and checksums outside the tracked repository.

No additional feature changes or broad refactors belong in this release. The user's request authorizes committing, pushing and publishing this repository release. Do not post to LinkedIn or another service as part of the GitHub release.

## Installation

Download the three assets from the published release or use Obsidian's plugin updater. Replace only `main.js`, `manifest.json`, and `styles.css` in `.obsidian/plugins/nosygraph/`, preserve `data.json`, and reload. This release remains beta software; retain vault backups.
