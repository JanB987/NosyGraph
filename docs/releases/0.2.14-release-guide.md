# NosyGraph 0.2.14 release verification

Repository: https://github.com/JanB987/NosyGraph

## Release contents

This patch removes the plugin-name settings heading rejected in the 0.2.13
checker preview and enables the matching lint rule. See [the release notes](0.2.14.md).
Source and installed runtime now share the `.obsidian/plugins/nosygraph` folder in the development vault.

## Release process

1. Keep `main` synchronized with `origin/main`; inspect every release change.
2. Set manifest, package, and both lockfile root versions to 0.2.14, with a
   `versions.json` compatibility entry of 1.5.0.
3. Run `npm run build`, `npm test`, `npm run typecheck`, `npm run lint`, and
   `git diff --check`. The release baseline is 560 tests in 104 files.
4. Stage the reviewed changes explicitly and commit on `main`.
5. Create annotated tag `0.2.14` at the release commit and push `main` and the
   tag without rewriting existing refs.
6. Create a draft GitHub release using `0.2.14.md` as the description, attach
   `main.js`, `manifest.json`, and `styles.css`, and verify their SHA256 hashes.
7. Publish as the latest normal release, retaining the plugin's existing beta
   status. Download the public assets and compare them with the staged build
   and installed runtime. Confirm `main` and the annotated tag match the commit.

Staging, checksums, verified downloads, and publication receipt are under
`.obsidian/release-staging/NosyGraph-0.2.14`, outside the Git repository.
Never include vault settings or `data.json` in the release assets.

## Maintainer smoke tests

- Run the Obsidian precheck against 0.2.14 and confirm that the settings-heading
  finding is gone. The exact matching rule is enabled locally.

- Reload NosyGraph and confirm version 0.2.14.
- Open a note as a graph and as a Lens. Add a YAML note link to a property in
  `rootNodeProperties`; confirm both views update without reopening.
- Repeat with plugin-level default root properties, including immediately after
  moving or pinning a node. Existing layout and expanded badges should remain.
- Close and reopen a saved Lens and confirm the new root is present.
- Check the settings sections in your active light/dark theme and in a narrow
  panel. Use Tab and Space/Enter to operate the advanced disclosures.
- Verify the unused mappings are hidden, Connected Base filters remain, and
  Legacy relationship direction appears only under Legacy compatibility.
- Confirm existing settings survive a reload. Test updating a copied vault
  using only the three release assets while preserving its `data.json`.
- In the Obsidian developer dashboard, run Check for new releases and inspect
  the 0.2.14 scan results. Do not mark that external checker as passed until
  the dashboard reports its result.
