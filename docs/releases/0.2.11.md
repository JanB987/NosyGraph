## NosyGraph 0.2.11

This release adds Lens LinkTypes and multiple connected Base views, and fixes
graph settings, Lens persistence, relationship matching, and Base filtering.

### Added and improved

- Define `linkType: lens` LinkTypes with one or more read properties and an
  optional `writeProperty`. Open independent Lens viewports from their badges,
  including multiple definitions using the same properties.
- Connect several Bases or Base views to one graph note:

  ```yaml
  connected_base_filter:
    - "[[db test.base#Graphs]]"
    - "[[db task.base#waiting]]"
  ```

  Matching notes are combined once per note path. Each view retains its own
  filters and limit. All connected Bases refresh the graph; a broken connection
  reports a diagnostic while valid connections continue working.
- Apply a Templater template to selected graph nodes when Templater is installed.
- Configure compact Lens-badge and pin visibility independently from label fading.
- Improve graph-node navigation for graph-capable notes, pinned panes, and Graph Tabs.

### Fixed

- Plugin-checker revision: retain Obsidian 1.5.0 compatibility with guarded
  newer storage APIs, a vault-scoped fallback, and migration on upgrade. Parse
  property IDs without requiring the newer Bases helper.
- Use Obsidian DOM helpers and a native Templater confirmation modal; correct
  paste-event, promise, lifecycle, and type handling; remove deprecated slider
  tooltip calls and restore the extracted engine's typed preview dependency.
- Inline grouping rules now survive close/reopen, including deleting every rule.
- Lens window close buttons and node badges both save their state. Ordered writes
  prevent earlier asynchronous events from replacing newer actions.
- Graph-capable Lens targets stay read-only; their visible instance state belongs
  to the original graph note unless the target is explicitly a persistent graph note.
- `file.path` comparisons retain directories and extensions.
- Unary `!` filters work, global/view filters combine with AND, and `not:` lists
  exclude notes matching any child condition.
- Unsupported Base expressions produce a diagnostic rather than a silent mismatch.
- LinkType property matching ignores casing consistently for outgoing/incoming
  discovery, aliases, cached links, and visible edges.
- Lens definitions retain stable identities, respect configured link formatting,
  and reconcile reference changes on rename/move.

### Validation and current limits

Automated validation passed: **551 tests across 103 files**, scoped architecture
typecheck, production build, and local lint checks for the reported review rules
(zero errors or warnings). The external plugin checker still needs to be rerun.

NosyGraph remains beta software. Manual large-vault, nested-Lens, Templater, and
clean-install checks are not complete. The production graph runtime is unchanged;
the replacement store/physics runtime and separate 0.3 development plugin remain
experimental. Lens LinkTypes currently support outgoing discovery. The Base
evaluator supports a subset of Bases expressions; use YAML `and`/`or` groups
instead of inline `&&`/`||`.

Persistence requires the configured graph-note identifier. A retained `o3graph`
block alone does not enable automatic writes. Existing single Base links remain
supported. Minimum Obsidian version remains **1.5.0**.

Install/update using the attached `main.js`, `manifest.json`, and `styles.css` in
`.obsidian/plugins/nosygraph/`, preserving your existing `data.json`, then reload
NosyGraph.
