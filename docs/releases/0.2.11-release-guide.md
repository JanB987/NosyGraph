# Finish or verify the NosyGraph 0.2.11 release

Repository: https://github.com/JanB987/NosyGraph

## Plugin-checker revision of the existing release

At the maintainer's explicit request, the checker fixes update the existing
`0.2.11` release rather than creating a new version. Its tag and all three
plugin assets are updated together to keep the source archive and binary
consistent. This is a specific exception to the normal published-tag policy
below. Existing installations of 0.2.11 must replace the three assets manually
and reload; the unchanged version cannot trigger a normal version update.

Run `npm.cmd ci`, `npm.cmd run lint`, `npm.cmd run typecheck`,
`npm.cmd test -- --pool=threads --maxWorkers=1`, and `npm.cmd run build`
before replacing assets. The lint command covers the reported review rules;
the external checker must still be rerun after publication.

The release tag must identify the intended release commit. Do not replace an
existing published tag. If commit/push was interrupted before completion:

1. Inspect the working tree and staged diff. The intended release message is
   `release: prepare NosyGraph 0.2.11`.
2. If the release commit does not exist yet, stage the intended repository
   changes, run `git diff --cached --check`, and create that commit on `main`.
3. Push `main` with `git push origin main`. If rejected because remote main has
   advanced, integrate the remote changes, resolve conflicts, rerun checks, and
   inspect the intended release commit before creating a tag. Do not force-push.
4. If `0.2.11` does not exist yet, create it at the verified release commit with
   `git tag -a 0.2.11 -m "NosyGraph 0.2.11"`. Push it with
   `git push origin 0.2.11`.

## Finish GitHub publication if needed

1. Check https://github.com/JanB987/NosyGraph/releases/tag/0.2.11 first. If it is
   already published with all assets, continue to verification below.
2. Open an existing draft, or create a release at
   https://github.com/JanB987/NosyGraph/releases/new using the existing `0.2.11`
   tag. Title: **NosyGraph 0.2.11**.
3. Paste the contents of `docs/releases/0.2.11.md` as the release description.
4. Attach `main.js`, `manifest.json`, and `styles.css` from the prepared staging
   directory below. Keep these exact filenames. Do not attach `data.json` or
   publish the separate `NosyGraph 0.3` development plugin.
5. Confirm the manifest says `0.2.11`, the tag targets the intended commit, and
   all three upload names/sizes match. Use the staging checksums for verification.
6. Review the remaining manual checks and the documented beta limitations. Set
   the release as latest, leave pre-release unchecked, and publish when ready.

## Verify installation and behavior

1. Download the three assets from the published release into a clean/copy test
   vault under `.obsidian/plugins/nosygraph/`. Enable NosyGraph and confirm version
   `0.2.11`. Preserve an existing installation's `data.json` when updating.
2. Open/close a Lens via its badge and its window close button; close/reopen the
   graph note and inspect its `o3graph` entries. Test independent/nested Lenses.
3. Add, edit, and clear grouping rules; confirm close/reopen and restart replay.
4. Test multiple connected Base views with overlapping results, changes to the
   second Base, removal of a connection, and an invalid connection diagnostic.
5. Test full-path filters, unary negation, global AND view filters, `not` lists,
   and incoming/outgoing mixed-case LinkType properties.
6. Test Lens LinkTypes sharing properties, relationship edits, pinned-pane and
   Graph Tab navigation, and Templater on a copied note selection.
7. Check the release assets and any Obsidian plugin-check feedback. Address
   confirmed regressions in a new patch version; never reuse the published tag.

Automated release checks: `npm.cmd run typecheck`,
`npm.cmd test -- --pool=threads --maxWorkers=1`, `npm.cmd run build`, and
`git diff --check`. No lint script is configured in this repository.
