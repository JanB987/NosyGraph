## NosyGraph 0.3.0

This release brings graph navigation and note editing into the same tab. It also makes it easier to move linked notes between graphs and lenses, add several relationships at once, and control where those relationships are stored.

### Edit notes without leaving the Graph Tab

The button in the upper-right corner now switches a Graph Tab between the graph and Obsidian's Markdown view. You can read and edit the selected note, including its properties, then return to the graph without replacing its root with the note you just opened.

When several notes are selected, a **Selected notes** list appears on the right. It shows full paths so notes with the same name are easy to distinguish. Click an entry to switch notes, or drag the divider to resize the list. The width is remembered for each graph note. With no selection, Markdown shows the graph's source note.

In **Automatic** mode, the selection comes from the graph pane you last used, including rendered graph embeds and nodes inside lenses. The usual active-note following rules still apply. The Markdown editor keeps its normal text shortcuts; Ctrl/Cmd+X cuts text when you are editing.

### Link a Graph Tab to one source tab

Use the chain button to choose a specific open tab as the source. The Graph Tab then follows only that tab's note and graph selection, even while you work in another graph pane. The link belongs to the tab itself, so navigating to a different note in the source tab keeps the connection.

Each Graph Tab saves its own mode and source binding with the workspace. If a linked source closes or cannot be restored, the Graph Tab reports that explicitly. It does not quietly start following another tab. Use the chain button to relink it or return to Automatic.

### Cut nodes from graphs, lenses, and expanded relationships

Use **Cut node / Cut nodes** in the context menu, **Ctrl/Cmd+X** on the canvas, or **Cut selected graph nodes** from the command palette. Cut now works across graph roots, classic and nested lenses, Lens LinkType viewports, and active property-based badge expansions.

Cut removes the references that introduce the selected node instances. For incoming relationships, it removes the reverse reference from the appropriate note. It does not delete note files. Body-link-only and filter-only nodes are skipped with an explanation, as are property values that cannot be safely separated.

The eligible note links go to the clipboard before any references are removed. Paste them into note bodies, frontmatter, property widgets, or a badge input, as often as needed. Open graph views and embeds refresh after the edits; partial failures are reported so the copied links remain available for recovery. Ctrl/Cmd+A still selects nodes across the focused graph and its open lenses.

### Paste several note links into a badge input

Alt-click a LinkType badge and paste links copied from graph nodes, wiki or Markdown links, or supported property lists. The input previews each note separately with its full path. Press **Enter** or **Add** to submit, remove individual entries, clear the batch, or cancel before writing.

The same input works with Force, Direction, and Lens LinkTypes. It uses the badge's existing direction and write-property rules: incoming badges write onto the pasted notes; outgoing and both-direction badges write onto the clicked note. Existing relationships in equivalent properties are skipped, and failed additions can be retried without repeating successful writes. Single-note search and creation are still available.

### Choose whether new links also join the graph

The badge input now has an **Also add to graph membership** toggle, also available in plugin settings. It defaults to On and stays at the value you choose.

With it enabled, notes added through search, creation, or batch paste also join the property that already lists the badge's parent node. If more than one property matches, the input asks which one to use. Inside a Lens LinkType, that membership belongs to the enclosing Lens source note and property. With the toggle off, only the badge relationship is added.

### Clearer Lens behavior and badge icons

Lens LinkType viewports now show their linked targets without adding the source node to the Lens. Lens membership keeps its viewport connector, but no longer produces ordinary node-to-node edges or force springs between notes that happen to be visible elsewhere. A separate Force Based or Direction Based LinkType can still render those relationships, including when it reads the same property.

LinkType badges now have mode-specific default icons: `scan-search` for Lens, `zap` for Force Based, `arrow-right` for Direction Based, and `git-branch` for Parent. Set `linkTypeIcon` in a LinkType note to use a registered Obsidian/Lucide icon name, emoji, symbol, or short text. For example, use `telescope`, `"🔭"`, or `"text:ABC"`. The property name can also be remapped in settings.

### Create graph notes from a template

Choose a Markdown file under **Graph note template → Template file** to create graph notes through Templater. Template output is preserved, including properties and note content. NosyGraph adds the configured graph identifier if it is missing; a conflicting identifier opens in Markdown for correction rather than being overwritten. Leave the setting empty to keep using the built-in graph note without Templater.
