# E10 artifact audit

Captured 2026-09-08. This audit identifies generated, diagnostic, migration, adapter, and experimental artifacts without deleting anything.

## Generated and local runtime artifacts

| Artifact | Classification | Decision |
|---|---|---|
| main.js | Tracked production bundle generated by npm run build | Retain. Never edit manually; rebuild and restore generated changes during source-only work. |
| styles.css, manifest.json, versions.json | Plugin release support files | Retain. They are part of the installed plugin contract. |
| package-lock.json, package.json, tsconfig files, esbuild.config.js | Build and validation support | Retain. |
| data.json | Obsidian plugin runtime settings; ignored by Git | Retain locally as vault state; do not treat it as source or architecture evidence. |
| node_modules | Local dependency installation; ignored by Git | Retain while validating; never commit or copy into a release artifact. |
| Bases - Graph-View/ | Nested ignored duplicate plugin tree, version 0.2.0, with its own main.js and node_modules | Cleanup candidate. It is separate from the current V2 tree and must be removed only after confirming no vault/plugin process references that path. |
| logs, traces, maps, coverage, temporary files | Generated artifact classes | None found in the current tree. |

## Shadow and parity diagnostics

The shadow and parity services are evidence support, not unused leftovers:

- GraphBadgeToggleShadowService and GraphBadgeToggleShadowComparator are constructed by GraphEngine for badge comparison.
- GraphPhysicsShadowInputService, GraphPhysicsShadowObserver, GraphPhysicsShadowSampleService, GraphPhysicsShadowDiagnostics, and GraphPhysicsParityService are exposed through explicit GraphEngine diagnostics.
- Their tests and documentation provide the evidence required by B01-B14, A8, D4, and the ownership audit.

Decision: retain until the corresponding parity gates are closed and LegacyOwnershipAudit reports them removable.

## Adapters and experimental classes

The similarly named adapters are separate migration boundaries, not duplicates:

- LegacyGraphSnapshotAdapter and LegacyGraphRuntimeState expose read-only legacy state.
- LegacyGraphPhysicsReadAdapter composes settings, constraint, container, and kinematics reads.
- LegacyBadgeCommandAdapter and LegacyGraphBadgeToggleExecutor bridge live badge behavior.
- GraphStoreBadgeToggleExecutor is the detached store implementation.
- Obsidian* adapters isolate host gateways.

StoreGraphRuntime, StagedGraphPhysicsEngine, GraphRuntimeModeSelector, GraphSceneStore, and GraphPhysicsExperimentRunner are experimental but referenced by tests and documentation. They must remain while store-mode activation and parity evidence are incomplete.

## Cleanup candidates and prerequisites

1. Nested Bases - Graph-View/ duplicate tree: confirm no process or vault configuration references it, then remove as one local cleanup change.
2. Historical documentation wording: update only after confirming the current implementation and evidence status.
3. Legacy adapters and shadow services: remove one owner at a time only after LegacyOwnershipAudit changes from blocked and all imports/tests are migrated.
4. Generated main.js: keep as the installed bundle; regenerate it from source for releases.

E10 is an inventory only. No artifact was deleted or edited manually.
